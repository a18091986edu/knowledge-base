# Сеть: интерфейсы, маршруты, порты, DNS

Базовая диагностика «почему не пингуется / не открывается порт». Углублённо **HTTP** (`curl`, заголовки) — в **Утилиты** и внешней документации.

---

## Адреса и маршруты

??? tip "ip"
    ```bash
    ip a
    ip addr show
    ip r
    ip route
    ```

---

## Открытые порты и процессы

??? tip "ss и lsof"
    ```bash
    ss -tuln
    ss -tulnp
    ss -tlnp
    lsof -i :80
    lsof -i :443
    ```

    Для всех PID в `ss` / `lsof` часто нужны права root.

---

## Доступность хоста и порта

??? tip "ping, nc, curl"
    ```bash
    ping -c3 8.8.8.8
    ping -c3 example.com

    nc -zv host 443
    curl -I http://IP
    curl ifconfig.me
    ```

---

## DNS

??? tip "nslookup и dig"
    ```bash
    nslookup example.com
    dig example.com
    ```

---

## Нет интернета

??? tip "Порядок проверки"
    ```bash
    ping 8.8.8.8
    ping google.com
    ```

    Нет ответа на IP — проблема канала/маршрута; IP есть, имена не резолвятся — **DNS**.

---

## Порт «закрыт» снаружи

??? tip "Локально vs файрвол"
    ```bash
    ss -tuln
    sudo ufw status
    systemctl status nginx
    ```

    Сервис может слушать только на `127.0.0.1` или быть закрыт **файрволом** — см. урок **Работа с фаерволом**.

## Чеклист

1. Есть ли адрес на интерфейсе? (`ip a`)  
2. Есть ли маршрут по умолчанию? (`ip r`)  
3. Резолвятся ли имена? (`dig`)  
4. Слушает ли процесс порт? (`ss`, `lsof`)  
5. Запущен ли сервис и нет ли блокировки в фаерволе?
