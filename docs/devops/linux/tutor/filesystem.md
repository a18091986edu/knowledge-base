# Файловая система: FHS, диски, inode, архивы

Иерархия каталогов, место на дисках, монтирование, жёсткие и символические ссылки, архивация.

## Иерархия каталогов (FHS)

??? tip "Зачем знать пути"
    Ориентир [FHS](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/index.html), на практике смотри ещё `man hier`.

    | Путь | Назначение |
    |------|------------|
    | `/` | Корень |
    | `/bin`, `/sbin` | Базовые утилиты (часто дубли в `/usr/bin`) |
    | `/boot` | Ядро, initramfs, загрузчик |
    | `/dev` | Устройства |
    | `/etc` | Конфигурация |
    | `/home` | Домашние каталоги пользователей |
    | `/root` | Домашний каталог root |
    | `/lib` | Библиотеки |
    | `/mnt`, `/media` | Ручное и авто-монтирование |
    | `/opt` | Сторонний софт |
    | `/proc`, `/sys` | Виртуальные ФС (ядро, процессы) |
    | `/run` | Runtime-данные |
    | `/srv` | Данные сервисов |
    | `/tmp` | Временные файлы |
    | `/usr` | Программы, документация |
    | `/var` | Логи, кэш, переменные данные |
    | `/lost+found` | Фрагменты после fsck |

## Место на диске и inode

??? tip "df и du"
    ```bash
    df -hT
    df -hi                    # inode: «место есть», а файлы не создаются
    du -sh /путь
    du -h --max-depth=1 /var | sort -h
    ncdu /var                 # интерактивно (пакет ncdu)
    ```

## Монтирование

??? tip "Блоки, UUID, fstab"
    ```bash
    lsblk -f
    findmnt
    mount
    sudo mount /dev/sdb1 /mnt/data
    sudo umount /mnt/data
    ```

    **`/etc/fstab`** — что монтировать при загрузке. Предпочтительно **UUID** или **LABEL**, а не только `/dev/sdX`: имена после перезагрузки могут сдвинуться.

## Inode и ссылки

??? tip "Модель: имя → inode → данные"
    - **inode** хранит метаданные и указатели на блоки данных; **имя** файла лежит в каталоге и ссылается на inode.
    - Проверка: `ls -li` — колонка inode.

??? tip "Жёсткая и символическая ссылка"
    **Жёсткая** (`ln`): тот же inode, те же данные; только в пределах одной ФС; на каталоги обычно нельзя.

    **Символическая** (`ln -s`): отдельный файл с путём; может вести на каталог или другой диск; при удалении цели «ломается». Для постоянных ссылок чаще используют **абсолютные** пути.

    ```bash
    ln файл жёсткая
    ln -s /opt/app/current /srv/app
    ls -li
    ```

    **Копия** (`cp`) создаёт новый inode и дублирует данные.

## RAID, LVM, разметка (концепты)

??? tip "Кратко для собеседования"
    - **RAID 0** — скорость без избыточности; один диск умер — потерян массив.
    - **RAID 1** — зеркало; **5/6** — с чётностью (зависит от `mdadm`, железа, ZFS…).
    - **LVM:** физический том → группа → логический том; удобно **расширять** тома (с ограничениями по ФС).
    - **MBR** — старая разметка; **GPT** — для больших дисков и типичный спутник UEFI.

## Архивация

??? tip "tar, gzip, zip"
    ```bash
    tar -czf arch.tar.gz файл_или_каталог
    tar -xvf arch.tar.gz
    tar -xvf arch.tar.gz -C /куда
    tar -tf arch.tar.gz

    gzip file
    gunzip file.gz
    gzip -k file

    zip -r arch.zip dir
    unzip arch.zip -d /куда
    ```
