# 🧰 Полезные утилиты



??? tip "🧠 MUST HAVE"
    ### 🧠 MUST HAVE
    ```bash
    htop        # монитор процессов (CPU, RAM, load)
    ncdu        # анализ диска по папкам
    tree        # дерево каталогов
    curl        # HTTP-запросы (API, web)
    wget        # скачивание файлов
    ```

    📌 Когда что использовать

    - `htop` → когда сервер тормозит, нужно найти “кто жрёт CPU/RAM”
    - `ncdu` → когда “диск заполнен, но непонятно чем”
    - `tree` → быстро понять структуру проекта / конфигов
    - `curl` → тест API, дебаг HTTP, проверка доступности
    - `wget` → скачивание файлов (особенно больших, с докачкой)



     📊 htop (процессы и ресурсы)

    📌 Что показывает:
    - CPU по ядрам
    - RAM / swap
    - список процессов
    - load average

    ```bash
    htop
    ```

     🔧 Основные действия внутри htop

    - ↑ ↓ → навигация
    - F6 → сортировка (CPU / MEM)
    - F9 → kill процесс
    - F3 → поиск
    - F5 → дерево процессов

     🔥 Полезные сценарии

    📊 Найти процесс, который грузит CPU:
    - открыть htop
    - отсортировать по CPU (F6)

    📊 Убить зависший процесс:
    - выбрать процесс
    - нажать F9

    📊 Найти процесс по имени:
    - нажать `/`
    - ввести имя



     💾 ncdu (анализ диска)

    📌 Что делает:

    - показывает размер папок
    - позволяет быстро найти “тяжёлые” директории

    ```bash
    ncdu /
    ncdu /var
    ncdu /home
    ```

    🔧 Управление

    - стрелки → перемещение
    - Enter → зайти в папку
    - d → удалить файл/папку
    - q → выход

    🔥 Кейсы


    📊 Диск заполнен:
    ```bash
    ncdu /
    ```

    📊 Найти большие логи:
    ```bash
    ncdu /var/log
    ```



     🌳 tree (структура каталогов)

    📌 Что делает:

    - показывает дерево файлов
    - помогает понять структуру проекта

    ```bash
    tree
    tree -L 2
    tree -a
    ```

    🔧 Полезные флаги

    - `-L 2` → ограничить глубину
    - `-a` → показать скрытые файлы
    - `-d` → только директории

    🔥 Кейсы


    📊 Посмотреть структуру проекта:
    ```bash
    tree -L 2
    ```

    📊 Найти скрытые файлы:
    ```bash
    tree -a
    ```



     🌐 curl (HTTP и API)

    📌 Что делает:

    - отправляет HTTP-запросы
    - используется для API и дебага

    🔧 Базовые запросы

    ```bash
    curl site.com
    curl https://api.example.com
    ```

    🔧 Часто используемые флаги

    ```bash
    curl -I site.com              # только заголовки
    curl -X POST api.com          # POST
    curl -d "a=1&b=2" api.com     # данные
    curl -H "Auth: token" api.com # заголовки
    curl -L url                   # редиректы
    ```

    🔥 Кейсы


    📊 Проверить доступность сайта:
    ```bash
    curl -I https://google.com
    ```

    📊 Отправить POST-запрос:
    ```bash
    curl -X POST -d "name=test" api.com
    ```

    📊 Проверить API:
    ```bash
    curl api | jq
    ```



     📥 wget (скачивание файлов)

    📌 Что делает:

    - скачивает файлы по HTTP/FTP
    - удобен для больших файлов

    🔧 Базовое использование

    ```bash
    wget file.zip
    ```

    🔧 Полезные флаги

    ```bash
    wget -c file.zip           # докачка
    wget -O name.zip url       # имя файла
    wget -q url                # тихий режим
    wget -r site.com           # скачать сайт
    ```

    🔥 Кейсы


    📊 Скачать большой файл:
    ```bash
    wget -c https://example.com/big.iso
    ```

    📊 Скачать и переименовать:
    ```bash
    wget -O app.tar.gz https://example.com/file
    ```



     🔗 Комбинирование (реальные сценарии)

    📊 Проверить API и отфильтровать:
    ```bash
    curl api | grep error
    ```

    📊 Скачать и распаковать:
    ```bash
    wget file.tar.gz && tar -xvf file.tar.gz
    ```

    📊 Найти большой файл и удалить:
    ```bash
    ncdu /var
    ```



    ⚠️ Частые ошибки

    - забывают `-L` в curl → не идут редиректы
    - используют `wget` вместо `curl` для API
    - не смотрят swap в htop
    - запускают `ncdu /` без sudo → не всё видно

??? tip "🔍 Поиск и навигация"
    ### 🔍 Поиск и навигация
    ```bash
    fzf     # интерактивный fuzzy-поиск
    fd      # быстрый find (поиск файлов)
    rg      # быстрый grep (поиск по содержимому)
    ```

    📌 Когда что использовать

    - `fzf` → когда нужно быстро выбрать из списка (файлы, история, процессы)
    - `fd` → когда нужно найти файл/директорию
    - `rg` → когда нужно найти текст (в коде, логах)

    📌 Простое правило:
    ```text
    файл ищем → fd
    текст ищем → rg
    выбираем из списка → fzf
    ```



     🔎 fd (поиск файлов)

    📌 Что делает:

    - ищет файлы и директории
    - быстрее и удобнее, чем `find`

    🔧 Базовое использование

    ```bash
    fd nginx
    fd config
    ```

    📌 Найдёт:
    - имена файлов
    - директории
    - без лишнего синтаксиса

    🔧 Полезные флаги

    ```bash
    fd -e conf            # по расширению
    fd -t f               # только файлы
    fd -t d               # только директории
    fd -H                 # включая скрытые
    fd -a                 # полный путь
    ```

    🔥 Кейсы


    📊 Найти все конфиги:
    ```bash
    fd -e conf
    ```

    📊 Найти все директории logs:
    ```bash
    fd logs -t d
    ```

    📊 Найти файл по части имени:
    ```bash
    fd nginx
    ```



     🔍 rg (ripgrep — поиск текста)

    📌 Что делает:

    - ищет текст внутри файлов
    - очень быстрый (лучше grep)

    🔧 Базовое использование

    ```bash
    rg "error"
    rg "nginx" .
    ```

    🔧 Полезные флаги

    ```bash
    rg -i "error"         # без регистра
    rg -n "error"         # номер строки
    rg -r "error" /var/log
    rg -v "info"          # исключить
    rg -g "*.log" error   # только по шаблону
    ```

    🔥 Кейсы


    📊 Найти ошибки в логах:
    ```bash
    rg "ERROR" /var/log
    ```

    📊 Найти строку в проекте:
    ```bash
    rg "TODO" .
    ```

    📊 Найти 500 ошибки:
    ```bash
    rg " 500 " access.log
    ```



     🔎 fzf (интерактивный поиск)

    📌 Что делает:

    - позволяет выбирать из списка в интерактивном режиме
    - работает с любым вводом (stdin)

    🔧 Базовое использование

    ```bash
    fzf
    ```

    📌 Ввод:
    - начинаешь печатать → фильтрация

    🔧 Частые комбинации

    ```bash
    history | fzf
    ls | fzf
    ps aux | fzf
    ```

    🔥 Кейсы


    📊 Найти команду из истории:
    ```bash
    history | fzf
    ```

    📊 Выбрать файл:
    ```bash
    fd | fzf
    ```

    📊 Найти процесс:
    ```bash
    ps aux | fzf
    ```



     🔗 Комбинирование утилит

    📌 Главная сила — в пайплайнах

    🔥 Примеры


    📊 Найти файл и открыть:
    ```bash
    fd | fzf | xargs bat
    ```

    📊 Найти строку и выбрать:
    ```bash
    rg "error" | fzf
    ```

    📊 Найти процесс и убить:
    ```bash
    ps aux | fzf | awk '{print $2}' | xargs kill
    ```



     🧠 Практические сценарии

    📊 Найти конфиг nginx:
    ```bash
    fd nginx.conf /
    ```

    📊 Найти ошибку в логах:
    ```bash
    rg ERROR /var/log
    ```

    📊 Быстро найти файл в проекте:
    ```bash
    fd | fzf
    ```

    📊 Найти строку и открыть файл:
    ```bash
    rg "TODO" | fzf
    ```



    ⚠️ Частые ошибки

    - используют `find`, когда есть `fd`
    - используют `grep`, когда есть `rg`
    - забывают про `-i` (регистр)
    - не используют `fzf` → теряют скорость

??? tip "📦 Работа с файлами"
    ### 📦 Работа с файлами
    ```bash
    bat     # просмотр файлов с подсветкой
    eza     # улучшенный ls
    duf     # использование диска
    ```

    📌 Когда что использовать

    - `bat` → читать файлы (логи, конфиги, код)
    - `eza` → анализ структуры директорий
    - `duf` → быстро понять состояние дисков

    📌 Простое правило:
    ```text
    посмотреть файл → bat
    посмотреть папку → eza
    проверить диск → duf
    ```



    📄 bat (просмотр файлов)

    📌 Что делает:

    - замена `cat`
    - подсветка синтаксиса
    - нумерация строк
    - удобен для чтения кода и конфигов

    🔧 Базовое использование

    ```bash
    bat file.txt
    ```

    🔧 Полезные флаги

    ```bash
    bat -n file.txt         # номера строк
    bat -A file.txt         # показать спецсимволы
    bat --style=plain file  # как cat
    ```

    🔥 Кейсы


    📊 Читать конфиг:
    ```bash
    bat nginx.conf
    ```

    📊 Посмотреть лог:
    ```bash
    bat app.log
    ```

    📊 Найти строку:
    ```bash
    bat file.txt | grep error
    ```



     📂 eza (расширенный ls)

    📌 Что делает:

    - замена `ls`
    - показывает:
      - права
      - размеры
      - git статус
      - дерево

    🔧 Базовое использование

    ```bash
    eza
    ```

    🔧 Полезные флаги

    ```bash
    eza -l             # подробный список
    eza -la            # включая скрытые
    eza -lh            # размеры в читаемом виде
    eza --git          # статус git
    eza -T             # дерево
    ```

    🔥 Кейсы


    📊 Посмотреть директорию:
    ```bash
    eza -la
    ```

    📊 Увидеть git изменения:
    ```bash
    eza -la --git
    ```

    📊 Показать структуру:
    ```bash
    eza -T
    ```



     💾 duf (использование диска)

    📌 Что делает:

    - показывает использование дисков
    - удобнее `df`

    🔧 Базовое использование

    ```bash
    duf
    ```

    🔧 Полезные флаги

    ```bash

    duf -only local
    ```

    🔥 Кейсы


    📊 Проверить свободное место:
    ```bash
    duf
    ```

    📊 Найти заполненный диск:
    ```bash
    duf -h
    ```



     🔗 Комбинирование утилит

    📌 Работа с файлами почти всегда через пайплайны

??? tip "🌐 Сеть"
    ### 🌐 Сеть
    ```bash
    curl    # HTTP-запросы / API
    http    # удобный HTTP-клиент (httpie)
    nc      # проверка TCP/портов (netcat)
    nmap    # сканирование портов
    ```

    📌 Когда что использовать

    - `curl` → базовый инструмент для HTTP/API
    - `http` → удобная альтернатива curl (читаемый вывод)
    - `nc` → проверить, открыт ли порт
    - `nmap` → полноценная диагностика сети

    📌 Простое правило:
    ```text
    API / HTTP → curl / http
    порт → nc
    сеть / сервис → nmap
    ```



     🌐 curl (HTTP и API)

    📌 Что делает:

    - отправляет HTTP-запросы
    - работает с API
    - показывает заголовки и тело ответа

    🔧 Базовое использование

    ```bash
    curl https://example.com
    ```

    🔧 Часто используемые флаги

    ```bash
    curl -I url                # только заголовки
    curl -X POST url           # метод
    curl -d "a=1&b=2" url      # данные
    curl -H "Auth: token" url  # заголовки
    curl -L url                # следовать редиректам
    curl -o file               # сохранить в файл
    curl -s url                # тихий режим
    ```

    🔥 Кейсы



    📊 Проверить сайт:
    ```bash
    curl -I https://google.com
    ```

    📊 Отправить POST-запрос:
    ```bash
    curl -X POST -d "name=test" https://api.com
    ```

    📊 Проверить API:
    ```bash
    curl https://api.com | jq
    ```

    📊 Скачать файл:
    ```bash
    curl -O https://example.com/file.zip
    ```



     🌐 http (httpie — удобный curl)

    📌 Что делает:

    - упрощённый curl
    - читаемый вывод (цвета, JSON)

    🔧 Базовое использование

    ```bash
    http GET example.com
    ```

     🔧 Примеры
    ```bash
    http GET api.com
    http POST api.com name=test
    http GET api.com Authorization:"Bearer token"
    ```

    🔥 Кейсы



    📊 Отправить POST:
    ```bash
    http POST api.com name=alex
    ```

    📊 Получить JSON:
    ```bash
    http GET api.com
    ```

    📌 Отличие от curl:
    - проще синтаксис
    - лучше читаемость
    - удобен для ручной работы



     🔌 nc (netcat — проверка портов)

    📌 Что делает:

    - проверяет доступность портов
    - может работать как TCP-клиент/сервер

    🔧 Базовое использование

    ```bash
    nc -zv host port
    ```

    🔧 Полезные флаги

    ```bash
    nc -zv localhost 80        # проверить порт
    nc -zv host 1-1000         # диапазон портов
    nc -l 8080                 # слушать порт
    ```

    🔥 Кейсы



    📊 Проверить порт:
    ```bash
    nc -zv google.com 443
    ```

    📊 Проверить диапазон:
    ```bash
    nc -zv localhost 20-100
    ```

    📊 Поднять простой сервер:
    ```bash
    nc -l 8080
    ```



     🔍 nmap (сканирование сети)

    📌 Что делает:

    - сканирует порты
    - показывает открытые сервисы
    - используется для диагностики и безопасности

    🔧 Базовое использование

    ```bash
    nmap host
    ```

    🔧 Полезные флаги

    ```bash
    nmap -p 80,443 host        # конкретные порты
    nmap -p- host              # все порты
    nmap -sT host              # TCP scan
    nmap -sU host              # UDP scan
    ```

    ⚠️ Требует root для некоторых режимов

    🔥 Кейсы



    📊 Проверить открытые порты:
    ```bash
    nmap localhost
    ```

    📊 Проверить веб-сервер:
    ```bash
    nmap -p 80,443 example.com
    ```



     🔗 Комбинирование утилит

    📊 Проверить API и распарсить:
    ```bash
    curl api.com | jq
    ```

    📊 Проверить порт и затем API:
    ```bash
    nc -zv host 80 && curl host
    ```

    📊 Найти открытые порты и проверить:
    ```bash
    nmap host | grep open
    ```



     🧠 Практические сценарии

    📊 Сервис не работает:
    ```bash
    nc -zv host 80
    ```

    📊 API не отвечает:
    ```bash
    curl -I api.com
    ```

    📊 Проверить редиректы:
    ```bash
    curl -I -L site.com
    ```

    📊 Проверить SSL порт:
    ```bash
    nc -zv host 443
    ```

    📊 Проверить, какие порты открыты:
    ```bash
    nmap host
    ```



    ⚠️ Частые ошибки

    - забывают `-L` в curl (редиректы)
    - используют curl вместо jq (не парсят JSON)
    - не проверяют порт перед дебагом сервиса
    - путают `nc` и `nmap`

??? tip "📊 Мониторинг"
    ### 📊 Мониторинг
    ```bash
    glances     # общий мониторинг системы
    htop        # процессы (CPU, RAM)
    iotop       # диск (I/O)
    iftop       # сеть (трафик)
    ```

    📌 Когда что использовать

    - `glances` → быстро получить полный обзор системы
    - `htop` → найти процесс, который грузит CPU/RAM
    - `iotop` → найти, кто нагружает диск
    - `iftop` → посмотреть сетевой трафик

    📌 Простое правило:
    ```text
    всё сразу → glances
    CPU/RAM → htop
    диск → iotop
    сеть → iftop
    ```



     📊 glances (общий мониторинг)

    📌 Что показывает:
    - CPU
    - RAM / swap
    - диск
    - сеть
    - процессы
    - load average

    ```bash
    glances
    ```

     🔧 Особенности

    - всё в одном окне
    - автообновление
    - цветовая индикация нагрузки

    🔥 Кейсы



    📊 Быстро понять, что происходит:
    ```bash
    glances
    ```

    📊 Проверить нагрузку сервера:
    ```bash
    glances
    ```



     📊 htop (процессы и CPU)

    📌 Что показывает:
    - список процессов
    - CPU по ядрам
    - RAM / swap


??? tip "🧾 Работа с текстом"
    ### 🧾 Текст
    ```bash
    grep    # поиск текста по шаблону
    awk     # обработка текста по колонкам
    sed     # потоковая замена/редактирование
    cut     # извлечение колонок
    sort    # сортировка строк
    uniq    # удаление дублей
    wc      # подсчёт строк/слов/байт
    ```

    📌 Когда что использовать

    - `grep` → найти строки (логи, ошибки)
    - `awk` → работать с колонками (таблицы, логи)
    - `sed` → массовая замена
    - `cut` → быстро вытащить колонку
    - `sort` → отсортировать
    - `uniq` → убрать дубли (только после sort!)
    - `wc` → посчитать

     🔍 grep (поиск)
    ```bash
    grep "error" file.txt
    grep -i "error" file.txt     # без регистра
    grep -r "error" /var/log     # рекурсивно
    grep -v "info" file.txt      # исключить
    ```

     🧠 awk (колонки)
    ```bash
    awk '{print $1}' file.txt
    awk -F: '{print $1}' /etc/passwd
    awk '{print $1, $3}' file.txt
    ```

     🔧 sed (замена)
    ```bash
    sed 's/foo/bar/' file.txt
    sed 's/foo/bar/g' file.txt
    sed -i 's/foo/bar/g' file.txt
    ```

     ✂️ cut (колонки)
    ```bash
    cut -d: -f1 /etc/passwd
    cut -d: -f1,3 file.txt
    ```

     🔢 sort (сортировка)
    ```bash
    sort file.txt
    sort -r file.txt
    sort -n file.txt
    ```

     🔁 uniq (уникальные строки)
    ```bash
    uniq file.txt
    uniq -c file.txt
    sort file.txt | uniq
    ```

     🔢 wc (подсчёт)
    ```bash
    wc -l file.txt
    wc -w file.txt
    wc -c file.txt
    ```

     🔗 Базовые пайплайны
    ```bash
    cat file.txt | grep error | sort | uniq -c
    cat /etc/passwd | cut -d: -f1
    dmesg | grep -i error
    ```

     🚀 Реальные кейсы (DevOps / практика)

    📊 Найти топ ошибок в логах:
    ```bash
    grep ERROR app.log | sort | uniq -c | sort -nr
    ```

    📊 Посчитать количество запросов по IP:
    ```bash
    awk '{print $1}' access.log | sort | uniq -c | sort -nr
    ```

    📊 Найти уникальные URL:
    ```bash
    awk '{print $7}' access.log | sort | uniq
    ```

    📊 Отфильтровать только 500 ошибки:
    ```bash
    grep " 500 " access.log
    ```

    📊 Заменить значения в конфиге:
    ```bash
    sed -i 's/localhost/127.0.0.1/g' config.txt
    ```

    📊 Посчитать строки:
    ```bash
    wc -l access.log
    ```

    📊 Найти пользователей в системе:
    ```bash
    cut -d: -f1 /etc/passwd
    ```

    📊 Найти активные процессы:

     🔐 ssh (удалённый доступ)

    - подключает к удалённому серверу
    - позволяет выполнять команды
    - работает по защищённому каналу



    🔧 Базовое использование

    ```bash
    ssh-copy-id user@host
    ```

    - не используют ключи



     📁 scp (копирование файлов)

    📌 Что делает:

    - копирует файлы через SSH
    - простой способ передачи



    🔧 Базовое использование

    ```bash
    scp file.txt user@host:/path
    ```



     🔧 Полезные варианты
    ```bash
    scp file user@host:/tmp           # загрузить
    scp user@host:/tmp/file .         # скачать
    scp -r dir user@host:/tmp         # папку
    scp -P 2222 file user@host:/tmp   # порт
    ```



    🔥 Кейсы



    📊 Загрузить файл:

    - копирует всё заново



    🔄 rsync (синхронизация)

    - синхронизирует файлы
    - копирует только изменения
    - используется для бэкапов и деплоя



    🔧 Базовое использование

    ```bash
    rsync -av source/ dest/
    ```



    🔧 Ключевые флаги
    ```bash

    rsync -v        # verbose
    rsync -z        # сжатие
    rsync --delete  # удалять лишние файлы
    ```



    🔧 Примеры
    ```bash
    rsync -av dir/ backup/
    rsync -av dir/ user@host:/backup/
    rsync -avz dir/ user@host:/backup/
    ```



    🔥 Кейсы



    📊 Синхронизация проекта:

    📊 Бэкап:

    📊 Зеркалирование:
    ```bash
    rsync -av --delete dir/ backup/
    ```

    ⚠️ Важно (частая ошибка)

    ```bash
    rsync -av dir/ backup/
    ```

    📌 означает:
    - копировать СОДЕРЖИМОЕ dir

    📌 означает:
