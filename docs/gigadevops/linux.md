# Linux: основы для инженера

Практичный обзор того, что обычно спрашивают на собеседованиях и что нужно в повседневной работе с серверами. Примеры ориентированы на **Debian/Ubuntu** (`apt`); для RHEL/CentOS/Fedora рядом даны аналоги.

!!! note "Дистрибутив"
    Пути к конфигам и имена пакетных команд отличаются. Если команда не найдена — установи пакет (`apt install …` / `dnf install …`) или используй эквивалент из таблицы в разделе про пакеты.

## Ядро и архитектура

**Зачем:** понять версию ядра, разрядность и тип системы — при отладке драйверов, контейнеров и несовместимых пакетов.

```bash
# Полная строка: ядро, hostname, архитектура, дата сборки ядра
uname -a

# Только версия ядра (удобно для сравнения с документацией CVE)
uname -r

# Архитектура машины (x86_64, aarch64, …)
uname -m
```

**Как читать `uname -r`:** обычно `5.15.0-91-generic` — это версия ядра и суффикс сборки дистрибутива.

## Память

**Зачем:** отличить нехватку RAM от проблем с диском (swap), увидеть кэш и реально доступную память.

```bash
# Человекочитаемо: total / used / free / shared / buff/cache / available
free -h
```

Строка **available** важнее **free**: в Linux свободная память часто «занята» под кэш, но ядро может отдать её приложениям.

```bash
# Детали из ядра (имена полей с заглавными буквами!)
grep -E "^MemTotal|^MemAvailable|^MemFree|^SwapTotal|^SwapFree" /proc/meminfo
```

!!! warning "Регистр в `/proc/meminfo`"
    В оригинальных шпаргалках часто пишут `Memtotal` — такого ключа **нет**. Нужны `MemTotal`, `MemAvailable`, `MemFree`.

## Пакетный менеджер и установленное ПО

### Debian / Ubuntu (`apt`, `dpkg`)

| Задача | Команда | Комментарий |
|--------|---------|-------------|
| Что ставили **вручную** (без авто-зависимостей) | `apt-mark showmanual` | Полезно перед «а что я вообще ставил на этот сервер» |
| Первые 20 ручных пакетов | см. конвейер ниже | `apt-mark showmanual` + `head` |
| Все установленные `.deb` | `dpkg -l` | Статус: `ii` = установлен нормально |
| Только успешно установленные | см. конвейер ниже | фильтр статуса `ii` |
| Поиск пакета по имени | `apt search nginx` | |
| Информация о пакете | `apt show curl` | Зависимости, описание, размер |
| Обновить индексы | `sudo apt update` | Не обновляет сами пакеты |
| Обновить пакеты | `sudo apt upgrade` | Без смены major-зависимостей |
| Полное обновление с решением зависимостей | `sudo apt full-upgrade` | Осторожно на проде без окна |

Конвейеры из таблицы:

```bash
apt-mark showmanual | head -20
dpkg -l | grep '^ii'
```

Пример: «есть ли пакет и какая версия»

```bash
dpkg -l | grep -E '^ii\s+nginx'
apt list --installed 2>/dev/null | grep nginx
```

### RHEL / Fedora (для сравнения)

| Debian | RHEL-подобные |
|--------|----------------|
| `dpkg -l` | `rpm -qa` или `dnf list installed` |

## UEFI или BIOS, загрузчик, конфиги

**Зачем:** понять, почему не грузится система, куда смотреть после обновления ядра, как править таймаут GRUB.

```bash
# UEFI: есть каталог efivars в sysfs
[ -d /sys/firmware/efi ] && echo "UEFI" || echo "Legacy BIOS (или гость без EFI)"

# Что лежит в /boot: ядра, initramfs, часто grub
ls -la /boot
```

Типичные файлы:

- **`/boot/grub/grub.cfg`** — сгенерированная конфигурация загрузчика (часто **не правят руками**).
- **`/etc/default/grub`** — переменные для генерации (после правок: `sudo update-grub` на Debian/Ubuntu).

```bash
# Посмотреть пункты меню и параметры ядра (осторожно: файл длинный)
sudo less /boot/grub/grub.cfg
```

## Журнал загрузок и прошлая сессия

**Зачем:** «вчера после ребута что-то отвалилось» — смотреть лог **предыдущей** загрузки.

```bash
# Список загрузок (индекс 0 — текущая, -1 — предыдущая)
journalctl --list-boots

# Лог **предыдущей** загрузки целиком
sudo journalctl -b -1

# Только ошибки за текущую загрузку
journalctl -b -p err..alert
```

## Этапы загрузки Linux (логика)

Упрощённая цепочка:

1. **Прошивка** (UEFI/BIOS) — инициализация железа, выбор устройства загрузки.
2. **Загрузчик** (часто **GRUB**) — выбор ядра и передача параметров командной строки.
3. **Ядро** — драйверы, монтирование root (часто через initramfs).
4. **PID 1** — **systemd** (или другой init) — юниты, цели (`multi-user.target`, `graphical.target`).
5. **Службы** — сеть, sshd, контейнеры и т.д.
6. **Login** — getty (TTY) или дисплей-менеджер (GUI).

```mermaid
flowchart LR
  A[UEFI/BIOS] --> B[GRUB]
  B --> C[Ядро + initramfs]
  C --> D[systemd]
  D --> E[Службы]
  E --> F[Вход пользователя]
```

Полезно смотреть порядок старта:

```bash
systemd-analyze
systemd-analyze blame | head -20
```

## Работа с файлами и текстом

| Команда | Назначение | Пример |
|---------|------------|--------|
| `cat` | Вывести файл целиком | `cat /etc/os-release` |
| `less` | Постраничный просмотр (выход — `q`) | `less /var/log/syslog` |
| `more` | Проще, чем `less` | |
| `touch` | Создать пустой файл или обновить время | `touch newfile` |
| `grep` | Поиск строки в файле | `grep ERROR app.log` |
| `grep -r` | Рекурсивно в каталоге | `grep -r "listen" /etc/nginx/` |
| `grep -E` | Расширенные регулярные выражения | `grep -E "foo|bar" file` |
| `find` | Поиск файлов по имени, типу, времени | см. ниже |

Примеры `find`:

```bash
# Файлы по маске, начиная с текущего каталога
find . -name "*.log"

# Только каталоги с глубиной не больше 2
find /var -maxdepth 2 -type d

# Файлы больше 100 МБ
find /home -type f -size +100M

# Изменённые за последние сутки
find /tmp -type f -mtime -1
```

## Файловая система (FHS — ориентиры)

Не жёсткий закон, но ожидания админов и софта такие:

| Путь | Обычно что лежит |
|------|-------------------|
| `/` | Корень дерева |
| `/home` | Домашние каталоги пользователей |
| `/root` | Домашний каталог root |
| `/etc` | Конфигурация системы и сервисов |
| `/var` | Изменяемые данные: логи, очереди, БД, кэш пакетов |
| `/tmp` | Временные файлы (часто очищается при перезагрузке) |
| `/usr` | Программы и библиотеки «для пользователей», документация |
| `/bin`, `/sbin` | Базовые утилиты (ещё дублируются в `/usr/bin`) |
| `/dev` | Узлы устройств (`/dev/sda`, `/dev/null`, …) |
| `/proc`, `/sys` | Виртуальные ФС: состояние ядра и процессов |

## Права на файлы и каталоги

Модель **rwx** для трёх классов: **владелец (u)** | **группа (g)** | **остальные (o)**.

```bash
ls -l /etc/passwd
# -rw-r--r-- 1 root root …
#  ^^^ ^^^ ^^^
#  u   g   o
```

### chmod: символьно и числом

```bash
# Владелец: чтение+запись; группа и остальные: только чтение
chmod u=rw,go=r file.txt

# Добавить исполняемость владельцу
chmod u+x script.sh

# Классика: r=4, w=2, x=1 → 755 = rwxr-xr-x
chmod 755 script.sh

# Рекурсивно (осторожно!)
chmod -R u+X,go-w somedir
```

### Специальные биты (кратко)

| Бит | На файле | На каталоге |
|-----|----------|-------------|
| **setuid** (`chmod u+s`) | процесс с правами **владельца файла** | редко |
| **setgid** (`chmod g+s`) | группа процесса = группа файла | новые файлы наследуют группу каталога |
| **sticky** (`chmod +t`, `1777`) | — | удалять чужие файлы в каталоге может только владелец файла (классика — `/tmp`) |

Пример sticky:

```bash
ls -ld /tmp
# drwxrwxrwt …  ← буква t в конце
```

### Смена владельца

```bash
sudo chown user:group file
sudo chown -R www-data:www-data /var/www
```

## Пользователи, пароли, группы

```bash
# Учётные записи: логин, uid, gid, домашний каталог, shell
getent passwd username
less /etc/passwd

# Хэши паролей и политика — только root (права 000/640)
sudo less /etc/shadow

# Группы
getent group sudo
less /etc/group
```

**Почему `shadow`:** пароли (или заглушки `!`, `*`) не хранят в world-readable `passwd`.

## Диски, inode, ссылки, RAID, LVM, разметка

### Место и использование

```bash
df -h                    # смонтированные ФС, занято/свободно
df -hi                   # inode — «сколько файлов ещё можно»

du -sh /home/user        # размер каталога
du -h --max-depth=1 /var | sort -h

ncdu /var                # интерактивный обзор (нужен пакет ncdu)
```

### Устройства и монтирование

```bash
lsblk -f                 # диски, разделы, UUID, точки монтирования
findmnt                  # что куда смонтировано

mount                    # список активных монтирований
sudo mount /dev/sdb1 /mnt/data
sudo umount /mnt/data
```

**`/etc/fstab`** — что монтировать при загрузке (UUID предпочтительнее `/dev/sdX`, потому что имена устройств могут переставиться после перезагрузки).

### inode (метаданные файла)

- У каждого файла/каталога на разделе есть **inode**: права, владелец, размер, время, указатели на блоки данных.
- **Имя файла** — запись в каталоге, которая ссылается на inode.
- Закончились inode при «есть место, но нельзя создать файл» — смотри `df -i`.

### Жёсткие и символические ссылки

```bash
# Жёсткая ссылка — то же inode, тот же контент; только в пределах одной ФС; на каталоги обычно нельзя
ln file.txt hardlink.txt

# Симлинк — отдельный файл с путём; может указывать на каталог и другой диск
ln -s /opt/app/current /srv/app
ls -l /srv/app
```

Если переименовать **цель** симлинка, относительный путь может сломаться — продумывай абсолютные пути для долгоживущих ссылок.

### RAID, LVM, MBR, GPT (концепты)

- **RAID 0** — чередование без избыточности: быстрее, но отказ одного диска = потеря массива.
- **RAID 1** — зеркало; **RAID 5/6** — чётность по нескольким дискам (зависит от контроллера/mdadm/ZFS).
- **LVM:** Physical Volume → Volume Group → Logical Volume; удобно **расширять** разделы без долгой переразметки (с оговорками по ФС).
- **MBR** — старая схема разделов (ограничения по размеру диска и числу разделов).
- **GPT** — современная разметка для больших дисков и UEFI.

## Bash: команды, потоки, фильтры

### Часто используемые флаги `ls`

```bash
ls -a          # включая скрытые (.config)
ls -l          # подробный список
ls -h          # размеры в K/M/G (с -l)
ls -d */       # только каталоги в текущей папке
```

### Перенаправления и конвейеры

```bash
# STDIN=0, STDOUT=1, STDERR=2

echo hello > file.txt           # перезапись
echo world >> file.txt        # дописать

cmd 2> errors.log             # stderr в файл
cmd > out.txt 2>&1            # всё в один файл
cmd &> out.txt                # то же в bash

cmd1 | cmd2                   # stdout cmd1 → stdin cmd2

# Дублировать вывод в файл и на экран
some_command | tee log.txt
some_command | tee -a log.txt   # append
```

### Мини-примеры `sed` / `awk`

```bash
# Заменить первое вхождение на строке
sed 's/foo/bar/' file.txt

# Удалить строки с шаблоном
sed '/DEBUG/d' app.log

# Печать 3-го поля по пробелам
awk '{print $3}' data.txt

# Сумма чисел в первом столбце
awk '{s+=$1} END {print s}' nums.txt
```

### Мониторинг и сеть (обзор)

```bash
htop                    # интерактивно процессы (пакет htop)
lsof -i :443            # кто слушает порт 443
ss -tlnp                # современная замена netstat для сокетов
```

```bash
# Нагрузка на диск (пакеты sysstat, iotop)
iostat -xz 1
sudo iotop -o
vmstat 1
```

## Процессы

### Типы и состояния

- **Интерактивные** — привязаны к терминалу (ожидают ввода).
- **Фоновые** — `command &` или запущены через shell в фоне (`jobs`).
- **Демоны** — долгоживущие службы (часто под **systemd**).

Состояния в `ps` / `top`:

| Код | Значение |
|-----|----------|
| **R** | running / runnable |
| **S** | sleeping (ожидание события) |
| **T** | stopped (сигналом) |
| **Z** | zombie — завершился, родитель не сделал `wait()` |

У **zombie** освобождены почти все ресурсы; «лечится» перезапуском или исправлением родительского процесса.

### Идентификаторы

- **PID** — идентификатор процесса.
- **PPID** — родительский PID.
- **UID** — от чьего имени процесс (реальный/эффективный может отличаться).

```bash
ps aux | less
ps -eo pid,ppid,user,cmd --sort=-%mem | head
pstree -p
```

### Приоритет CPU и I/O

```bash
nice -n 10 long_running_cmd    # меньше приоритет (больше «nice»)
renice +5 -p 1234

ionice -c2 -n7 -p 1234         # класс best-effort, приоритет внутри класса
```

`stress` и `fio` — **синтетическая нагрузка** для тестов (не на проде без контроля).

## Шпаргалка «что запустить первым» при проблемах

1. `uptime`, `free -h`, `df -h`, `df -hi`
2. `journalctl -b -p err..alert` или `dmesg -T | tail`
3. `ss -tlnp` / `ip a` — сеть и порты
4. `systemctl --failed`
