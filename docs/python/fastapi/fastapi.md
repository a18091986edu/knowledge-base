### HTTP запросы

1. **Стартовая строка**



**Формат:** `МЕТОД ПУТЬ ВЕРСИЯ`(**от клиента**)
**Формат:** `ВЕРСИЯ КОД_СОСТОЯНИЯ ОПИСАНИЕ`(**от сервера**)

- **МЕТОД** (заглавными): GET, POST, PUT, DELETE, PATCH и др.
- **ПУТЬ** = параметр пути + query-строка (`?key=value&key2=value2`)
- **ВЕРСИЯ**: HTTP/1.0, HTTP/1.1, HTTP/2, HTTP/3
- **КОД СОСТОЯНИЯ**: трехзначное число, указывает резальтат обработки запроса
- **ОПИСАНИЕ**: человекочитаемый текст

**Пример:** `POST /users/42/profile HTTP/1.1`



| HTTP Глагол     | Ожидаемый статус        | Ожидаемый ответ                                                     |
|----------------|-------------------------|---------------------------------------------------------------------|
| POST (создание) | 201 Created             | Новый URI созданного ресурса в заголовке Location                   |
| GET (чтение)    | 200 OK                  | Данные ресурса в теле ответа                                        |
| PUT (обновление)| 200 OK                  | Обновлённые данные ресурса, либо 404 Not Found, если ресурс не найден|
| DELETE (удаление)| 204 No Content         | Пустой ответ, не содержащий тела                                    |
| OPTIONS         | 200 OK                  | Список доступных методов HTTP в заголовке Allow                     |
| HEAD            | 200 OK                  | Только заголовки ответа, без тела                                   |


**Классификация кодов состояния HTTP**

**1xx (Информационные)**

Запрос получен, сервер продолжает обработку. Обычно не видны пользователю.

---

**2xx (Успешные)**

Запрос обработан успешно.

| Код | Значение |
|-----|----------|
| 200 OK | Запрос успешен |
| 201 Created | Ресурс создан |
| 204 No Content | Успешно, но тело ответа пустое |

---

**3xx (Перенаправления)**

Клиент должен выполнить дополнительные действия.

| Код | Значение |
|-----|----------|
| 301 Moved Permanently | Ресурс постоянно перемещён |
| 302 Found | Ресурс временно перемещён |
| 304 Not Modified | Ресурс не изменился |

---

**4xx (Ошибки клиента)**

Ошибки на стороне клиента.

| Код | Значение |
|-----|----------|
| 400 Bad Request | Некорректный запрос |
| 401 Unauthorized | Не авторизован |
| 403 Forbidden | Нет прав доступа |
| 404 Not Found | Ресурс не найден |
| 405 Method Not Allowed | Метод не разрешён |
| 409 Conflict | Конфликт ресурсов |
| 415 Unsupported Media Type | Неподдерживаемый формат данных |
| 418 I'm a teapot | Шуточный код ("я чайник, не варю кофе") |
| 422 Unprocessable Entity | Невалидные данные (понятно, но нельзя обработать) |

---

**5xx (Ошибки сервера)**

Ошибки на стороне сервера.

| Код | Значение |
|-----|----------|
| 500 Internal Server Error | Внутренняя ошибка сервера |
| 502 Bad Gateway | Неверный ответ от вышестоящего сервера |
| 503 Service Unavailable | Сервер временно недоступен |
| 504 Gateway Timeout | Таймаут от вышестоящего сервера |


2. **Заголовки**


| Заголовок | Назначение |
|-----------|------------|
| `Host` | Обязательный — какой домен на сервере |
| `User-Agent` | Информация о клиенте (браузер, бот) |
| `Accept` | Какой формат ответа ждёт клиент (`application/json`, `text/html`) |
| `Authorization` | Токен/логин-пароль для аутентификации |
| `Content-Type` | Формат тела запроса (`application/json`, `multipart/form-data`) |
| `Content-Length` | Размер тела в байтах |
| `Cache-Control` | Директивы кэширования |
| `If-None-Match` | Условный запрос (ETag — версия ресурса) |
| `Cookie` | Данные сессии от сервера |
| `Origin/Referer` | Откуда пришёл запрос (безопасность) |
| `Idempotency-Key` | Уникальный ключ операции (для повторных попыток) |

---

3. **Тело** (пустая строка после заголовков)

- **Когда есть:** POST, PUT, PATCH (изменяют ресурс)
- **Когда нет:** GET, HEAD, OPTIONS, DELETE (по стандарту)

**Форматы тела:**
- `application/json` — API, данные в JSON
- `multipart/form-data` — файлы и формы
- `chunked` — потоковая передача (с `Transfer-Encoding: chunked`)
